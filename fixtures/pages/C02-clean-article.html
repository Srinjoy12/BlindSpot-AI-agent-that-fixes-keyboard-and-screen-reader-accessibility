WCAG 2.2 explained: what changed and why it matters

15 September 2026 by Jane Smith 8 min read

Web Content Accessibility Guidelines 2.2 became a W3C Recommendation in October 2023, introducing nine new success criteria and removing one. If your team has not yet updated its accessibility checklist, here is what you need to know.

What is new in WCAG 2.2?

WCAG 2.2 adds criteria focused on mobile usability, cognitive accessibility, and refinements to focus management. The most impactful additions for keyboard users are the two focus-related criteria.

Focus Not Obscured (Minimum) — SC 2.4.11

When a user interface component receives keyboard focus, the component must not be entirely hidden due to author-created content. This addresses the common problem of sticky headers covering focused elements.

"Sticky headers are the most common source of SC 2.4.11 failures we see in audits."

Dragging Movements — SC 2.5.7

All functionality that uses a dragging movement for operation must be achievable with a single pointer without dragging. This matters for sliders, sortable lists, and map interfaces.

What changed from WCAG 2.1?

  • SC 4.1.1 (Parsing) was removed — modern browsers handle malformed markup well enough that this check no longer provides value.
  • SC 2.4.7 (Focus Visible) was upgraded from a WCAG 2.1 AA criterion to a revised criterion in 2.2.
  • Several criteria were clarified with better normative language.

How to audit for WCAG 2.2 compliance

  1. Start with an automated scanner to catch the easy wins — missing alt text, colour contrast, heading structure.
  2. Manually test with a keyboard. Tab through every interactive control and verify that focus is always visible and that you can complete every task.
  3. Test with a screen reader — NVDA on Windows, VoiceOver on macOS and iOS, TalkBack on Android.
  4. Use BlindSpot to catch the runtime barriers that static scanners miss.
